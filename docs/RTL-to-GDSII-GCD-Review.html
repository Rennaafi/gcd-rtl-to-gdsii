RTL → GDSII: Physical Design Review

Design: GCD (Greatest Common Divisor unit)  ·  Flow: OpenROAD-flow-scripts (ORFS)  ·  Primary platform: nangate45 (cross-checked against sky130hd & ibex_core)

Personal review notes from a hands-on walkthrough of the full digital physical design flow — what each stage does, why it exists, how to read real signoff data, and how to actually fix a timing problem instead of just loosening the clock.

1. The Big Picture

RTL describes behavior — what a circuit should do. GDSII describes geometry — exact shapes, on exact layers, at exact coordinates, ready for a fab to manufacture as silicon. Everything between the two is the process of turning "what it should do" into "where every transistor and wire physically sits."

RTL

Verilog/VHDL. A register adds two numbers on a clock edge. No size, no position, no physical reality yet.

Netlist

A list of standard cells (AND, NAND, flip-flops…) wired together, implementing the same behavior — still no physical placement.

Layout

Every cell has an (x,y) position, every wire is drawn on a real metal layer.

GDSII

The final, checked, manufacturable geometry file streamed out for the fab.

Important distinction we learned the hard way

A flow finishing and producing a .gds file does not mean the chip works. ORFS will happily place, route, and stream out GDSII even with timing violations. Physical completion and timing signoff are separate questions — see §5.

3. Key Vocabulary

PDK — Process Design Kit

The "materials catalog" for a specific manufacturing process: what standard cells look like, their delays, layer/spacing rules. nangate45 is a synthetic academic 45nm-like library (fast to run, not real silicon). sky130hd is SkyWater's actual open-source 130nm process — real, fabricatable, but an older/slower node.

SDC — Synopsys Design Constraints

The file where you declare timing intent: what's the clock, how fast, how much I/O margin. STA checks the design against this file — it doesn't invent a target itself.

set clk_period 0.5
create_clock -name core_clock -period $clk_period [get_ports clk]
set_input_delay  [expr $clk_period*0.2] -clock ... $non_clock_inputs
set_output_delay [expr $clk_period*0.2] -clock ... [all_outputs]

STA — Static Timing Analysis

Checks every register-to-register (and I/O) path using worst-case delay models — not simulation with test vectors. Two checks per path:

  • Setup — does data arrive with time to spare before the next clock edge? Fail → chip can't run this fast (or fails outright).
  • Hold — does data stick around long enough not to be overwritten before the current edge finishes registering it? Fail → chip is broken at any speed (a race condition, not a speed limit) — more dangerous than a setup fail.

Slack, WNS, TNS

Slack = required arrival time − actual arrival time. Positive = safe margin. Negative = the signal arrived too late (setup) or too early (hold) — a real functional risk, not just "slower."

WNS (Worst Negative Slack) = the single worst violation. TNS (Total Negative Slack) = sum of all violations across all paths. Signoff target: WNS ≥ 0, TNS = 0.

4. The Design: GCD

Computes the Greatest Common Divisor via the classic subtraction-based Euclidean algorithm:

while b != 0:
    if a < b: swap(a, b)
    else:     a = a - b
return a

Split into two standard blocks — a pattern worth internalizing for any datapath design:

ctrl — the FSM ("brain")

3 states: IDLE (latch inputs) → CALC (iterate swap/subtract every cycle until b==0) → DONE (hold result until accepted) → back to IDLE.

dpath — the datapath ("muscle")

a_reg/b_reg hold the operands; a comparator checks a<b; another checks b==0; a subtractor computes a-b; muxes pick what feeds back into the registers each cycle.

Ports: clk, req_msg[31:0] (two packed 16-bit operands in), req_val/req_rdy (input handshake), resp_msg[15:0] (result out), resp_val/resp_rdy (output handshake), reset.

Note: the RTL we used is auto-generated by PyMTL (a Python HDL), hence hashed module names like GcdUnitCtrlRTL_0x4d0fc71ead8d3d9e — not representative of typical hand-written style, but functionally a clean, small teaching example.

5. Our Journey — Diagnose & Fix a Real Violation

Attempt 1 — an unrealistic clock (nangate45, 0.25 ns = 4 GHz)

Real achievable period (period_min)0.41 ns → fmax ≈ 2.44 GHz
Total power6.38 mW

The worst path, traced directly from OpenSTA's report_checks -path_delay max (not guessed — read straight off the tool):

Startpoint: dpath.a_reg.out[12] (register) → NAND2 → INV → NOR2 → NAND2 → NOR2 → AND2 → NAND2 → NAND3 → NAND2 → BUF_X8 → INV_X8 → NAND2 → NAND3 Endpoint: dpath.b_reg.out[6]/D (register) 14 logic gates deep · arrival 0.45 ns · required 0.29 ns slack = -0.16 ns (VIOLATED)

This path is the a<b comparator result rippling through the FSM's control logic and back through b_mux into b_reg — a control-dependent datapath path, longer than a naive read of the RTL would suggest.

Root cause

Not a bug — an unrealistic constraint. We asked for something the physical logic cannot do. report_clock_min_period told us directly: the real ceiling is 0.41 ns.

The fix — relax to a real target (0.5 ns = 2 GHz)

MetricBefore (0.25 ns)After (0.5 ns)
WNS-0.16 ns+0.04 ns
TNS-7.18 ns0.00 ns
Setup violations510
Total power6.38 mW2.22 mW -65%

Why power dropped too

Two compounding effects: (1) dynamic/switching power scales with clock frequency — a slower clock means less switching per second; (2) the optimizer was no longer fighting an impossible target — it stopped inserting extra buffers and up-sizing cells to chase 4 GHz, so it settled on smaller, cheaper gates. An unrealistic constraint doesn't just fail timing — it actively makes the chip bigger and hungrier, because the tools burn area/power trying (and failing) to satisfy it.

8. Beyond "Just Relax the Clock" the real challenge

Loosening the SDC is the easiest lever, but it's a global fix — it slows down the entire chip to save one bad path. Real physical design engineers reach for more surgical tools first. Ordered from least to most invasive, all explained against our actual violated path (§5): a_reg → comparator/control logic → b_mux → b_reg.

1. Cell sizing / ECO

least invasive
tool-driven, sometimes needs a manual push

Swap slow, small-drive-strength gates along the critical path for bigger/faster variants of the exact same logic function (e.g. NAND2_X1 → NAND2_X4). Nothing about the RTL, netlist connectivity, or floorplan changes — just the physical size of existing cells.

We actually already saw this happen automatically: the timing_repair_buffer instances in our metrics (58 at 0.5 ns, up to 166 at 0.3 ns) are exactly the tool running this ECO on its own during optimization.

Try it yourself

cd ~/OpenROAD-flow-scripts/flow
make DESIGN_CONFIG=./designs/nangate45/gcd/config.mk gui_final
# in the OpenROAD Tcl console:
report_checks -path_delay max
resize_instance <instance_name> <bigger_cell_name>
report_checks -path_delay max   ;# did slack improve?

2. Logic restructuring

same behavior, different gate-level shape

Re-implement the identical Boolean function with a shallower/different gate topology — e.g. our 14-gate ripple-style comparator chain could become a shallower tree structure, trading area for logic depth. Must be done at synthesis (different technology mapping) or via RTL rewrite, then reverified for logical equivalence.

This is what config knobs like ADDER_MAP_FILE and SWAP_ARITH_OPERATORS (seen in the sky130hd/ibex configs) actually control — picking different arithmetic gate-level implementations.

3. Pipelining

most invasive — changes microarchitecture/latency

Insert an extra register stage to break the long comparator→mux→register path into two shorter cycles — e.g. register is_a_lt_b on its own cycle instead of consuming it combinationally in the same one. Buys much higher clock frequency, costs latency (more cycles per GCD iteration) and requires real RTL/FSM redesign plus functional re-verification. This is a different microarchitecture, not just a different implementation of the same one.

4. Floorplan / placement tweaks

attacks wire delay specifically

Constrain where a_reg, b_reg, and the comparator sit relative to each other (placement regions/groups) so the wires between them are physically shorter. Recall our congestion heatmap flagged exactly this region as a hotspot — part of that 0.45 ns delay is wire delay from cells sitting far apart or routed through congestion, not pure gate delay. This technique attacks only that component.

5. Buffering / multi-Vt swaps

targeted physical techniques

Insert dedicated buffers to fix slew on a long wire, or swap specific cells on the critical path to a low-threshold-voltage (low-Vt) variant — same logic function, faster switching, at the cost of higher leakage. Unlike relaxing the whole clock (blunt, affects every path equally), this is a scalpel: only the cells that need it get faster/leakier, the rest of the chip keeps its default, lower-leakage cells.

nangate45 is single-Vt (academic library), so this move is more illustrative there; sky130hd ships real hd/hs/ls Vt families — a better place to actually try it.

The actual challenge

Go back to the original violating case (nangate45/gcd @ 0.25 ns, WNS -0.16 ns) — but this time, instead of touching clk_period in the SDC, try to close the gap using technique #1 (cell sizing/ECO) alone, interactively in the OpenROAD GUI. How much of that -0.16 ns can you claw back without slowing the clock down at all? That's the real day-to-day job of a PPA/physical design engineer.

10. Glossary / Quick Reference

PDK
Process Design Kit — the fab's rulebook + cell library.
SDC
Synopsys Design Constraints — where you declare clock/timing intent.
STA
Static Timing Analysis — checks every path against the SDC using worst-case delay models.
Setup violation
Data arrives too late for the next clock edge — a speed problem.
Hold violation
Data arrives too early / overwritten too soon — a race-condition, broken at any speed.
Slack
Required time − actual time. Negative = violation.
WNS / TNS
Worst / Total Negative Slack — the two headline signoff numbers.
fmax
The real maximum frequency the current implementation can run at, per STA — not what you asked for in the SDC.
CTS
Clock Tree Synthesis — builds the balanced buffer network distributing the clock.
DRC / LVS
Design Rule Check / Layout-vs-Schematic — geometric and logical-equivalence signoff checks (not yet covered hands-on in this review — a good next topic).
ECO
Engineering Change Order — a small, targeted fix (cell swap, buffer insertion) applied after the main flow, instead of re-running everything.
Vt (threshold voltage)
Lower Vt = faster switching but more leakage power; higher Vt = slower but leaner. Real PDKs offer multiple Vt cell families to trade locally.
